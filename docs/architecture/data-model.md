# TapTalk Data Model

## Tables

- `users`: account identity, credential hash, role, and lifecycle timestamps.
- `vocabulary_entries`: canonical English phrase, optional phonetics, original German display value, and lifecycle timestamps.
- `vocabulary_answers`: normalized accepted answers linked to a vocabulary entry; alternatives are separate rows.
- `vocabulary_imports`: administrator import metadata, status, counts, and timestamps.
- `user_preferences`: one row per user for direction, vocabulary filter, session length, and repetition preference.
- `learning_attempts`: immutable user-attributed answer history, matching result, score delta, prompt, and timestamp.
- `sessions`: opaque authenticated session hashes with expiry and revocation timestamps.
- `schema_migrations`: applied migration identifiers and timestamps.

## Integrity rules

- All identifiers are opaque text values generated by the application.
- Usernames are unique case-insensitively through a unique index.
- Accepted answers are unique per vocabulary entry by normalized value.
- Attempts reference both a user and vocabulary entry and are retained when an entry is removed by using `ON DELETE RESTRICT`.
- User-owned preferences, sessions, and attempts are removed with the user according to the account deletion policy.
- Import metadata is retained independently of vocabulary rows for auditability.
- Timestamps are stored as UTC ISO-8601 text.
- Indexes support username lookup, session expiry cleanup, attempt history by user, and repeated-error selection.

## Migration strategy

Migrations are ordered SQL files with immutable identifiers. The API applies unapplied migrations in a transaction before readiness. A migration records its identifier only after all statements succeed. Development reset means deleting the configured SQLite file and running migrations again; production reset is not a supported operation.

## Data minimization

The database stores credential hashes rather than plaintext credentials. Submitted answers are retained because attempt history is a product requirement; retention and account deletion details remain `OPEN DECISION 011`.
